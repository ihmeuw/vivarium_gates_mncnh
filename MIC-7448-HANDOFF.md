Repo: `vivarium_gates_mncnh`

## Goal

`vivarium-testing-utils` (vtu) was split into three packages. Move mncnh onto them:

- `pytest-vivarium` — the pytest plugins
- `vivarium-validation` — the automated V&V tooling
- `vivarium-fuzzy-checker` — `FuzzyChecker`

## What is already done (committed and pushed)

### pyproject.toml

- `test` extra: `vivarium-testing-utils>=0.7.4` → `pytest-vivarium>=0.2.0` + `vivarium-fuzzy-checker>=0.5.0`
- `validation` extra: `vivarium-testing-utils[validation]` → `vivarium-validation[gbd]>=0.4.0`
  - The `[gbd]` extra is what supplies `vivarium-inputs`, which vtu's `[validation]` extra carried.
- `requires-python` needed no change — `main` is already `>=3.11`, which all three new packages require.

## Gotchas found along the way

- **`pytest_vivarium` cannot run with xdist disabled.** Its
  `pytest_xdist_auto_num_workers` hook needs the xdist plugin loaded; `-p no:xdist`
  produces a `PluginValidationError` INTERNALERROR. mncnh's `addopts = "-nauto"` is fine.
- The local `~/repos/vivarium_testing_utils` checkout is **stale** (pre-split, no
  `vivarium.testing_utils` namespace at all). Don't use it as the mapping reference; the
  released 0.7.6 sdist or the `vivarium-suite/libs/{pytest-vivarium,validation,fuzzy-checker}`
  trees are the real sources.
- No local conda env had vtu 0.7.x (newest was 0.5.5), which is why a fresh env build
  was necessary rather than reusing an existing one.
- A leftover local env `mic7448_simulation` exists on the WSL box and can be deleted.
